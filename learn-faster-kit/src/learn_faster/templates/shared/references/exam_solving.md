# Solving Layer — the Exam Operating Manual

Prediction says *what* will be asked. This reference says *how the student executes it* under time pressure. Read after `prediction-and-analysis.md`, before building output.

**Governing principle.** Never stop at "here is what this concept means." For every exam-relevant topic reach: *what it means → how the professor asks it → how to recognize it → exactly what to do → what to write/select → the trap → how to check yourself.* Optimize for high-fidelity exam performance from the student's own material, not textbook completeness.

## 1. Question-type recognition system

For every major question type present in the material, build:

**IF I SEE THIS → IT MEANS THIS → I SHOULD DO THIS**

Each entry carries: recognition clues from the wording · data to identify · what is actually being asked · method/formula · exact solving sequence · the tempting wrong method · how to verify.

Use the **professor's actual wording from past exams** as the recognition clue, not generic textbook phrasing.

Categories activate only when present in the material — never force them. Candidates: calculation/problem · definition/recall · compare/contrast · mechanism/process · interpretation · graph/table analysis · experimental design · data interpretation · diagram labeling · identification · classification · protocol/procedure · troubleshooting · case/application.

## 2. Step-by-step solving procedures

For every high-priority procedural type, give a mechanical numbered procedure a beginner can follow *without already understanding the whole subject*:

**Given → Identify → Choose method → Execute → Interpret → Check** (or the subject's equivalent).

- **Calculation:** values to extract · formula selection · what each symbol means · substitution · calculation · units · final answer · interpretation · sanity check.
- **Conceptual:** identify the tested concept · minimum facts required · how to separate the answer from distractors · keywords that matter · common misconceptions.
- **Practical/lab:** what to identify first · decision points · action sequence · expected observations · interpretation · common errors · how the professor's material frames the answer.

## 3. Beginner-to-exam bridge

Never assume reading the explanation means being able to answer. For each major topic, bridge explicitly:

**CONCEPT → RECOGNITION → METHOD → EXECUTION → EXAM ANSWER**

Answer: What is this? How do I recognize the question is testing it? What do I do first? Next? What exactly do I write or select? How do I know my answer is reasonable?

When a topic is mathematically or procedurally dense, prioritize this execution layer over more theory.

## 4. Worked-example escalation

For high-priority topics, when the sources support it: (1) explain the concept simply → (2) show a professor/example problem solved → (3) annotate *why* each step was chosen → (4) show the same pattern from a past exam → (5) name what changed and what stayed invariant → (6) give a reusable solving template.

Do **not** invent practice questions when real examples exist. If an invented micro-example is genuinely needed to explain a procedure, mark it **[Illustrative example, not from the course]**.

## 5. Exact answer templates

For constructed responses, give exam-ready structures, adapted to the professor's terminology and expected depth. Activate only where useful — don't template everything. For Egyptian papers, build one template per stem the doctor uses (Give reasons, Write short notes, Compare, ✓/✗ with correction…) following `prediction-and-analysis.md` §3b, with about one point per mark (§1b).

- **Definition:** *[Term] is ______. Its key feature/function is ______.*
- **Compare/contrast:** *Both ______ and ______ share ______. However, ______ differs because ______.*
- **Mechanism:** *First ______ → then ______ → resulting in ______.*
- **Calculation:** *Given ______ · Formula ______ · Substitution ______ · Result ______ · Interpretation ______*
- **Data interpretation:** *Observation ______ · This indicates ______ because ______ · Therefore ______*

## 6. Mark-earning structure (within a question)

Where model answers or past papers reveal allocation, identify what earns each mark, which steps are essential, what counts as complete, and where partial credit exists. **If allocation can't be established, do not invent it** — label components "essential for a complete answer."

For written questions, always separate: **MUST INCLUDE** · **GOOD TO INCLUDE** · **UNNECESSARY DETAIL** — so the student doesn't write a textbook chapter when the professor wants four lines.

## 7. Answer-checking layer

For procedural/calculation topics: **ANSWER → QUICK CHECK**. Adapt checks to the subject — units · magnitude · order of magnitude · sign/direction · logical consistency · biological plausibility · expected trend · does it actually answer the question · were all parts answered.

For MCQs, give a rapid elimination strategy when the material supports one.

## 8. Distractor analysis

Turn the professor's MCQ style into a reusable system:

**QUESTION → TEMPTING WRONG ANSWER → WHY IT LOOKS RIGHT → WHY IT IS WRONG → CORRECT RULE**

Prioritize distractors matching: common misconceptions · reversed relationships · terminology confusion · similar-looking concepts · calculation and unit and sign errors · missing conditions · overgeneralization · cause vs correlation · adjacent mechanisms · "almost correct" statements. Use **actual distractors from past exams** whenever available.

## 9. Stuck-recovery protocol

Per major question type: (1) identify what is definitely being asked → (2) list knowns → (3) name the relevant topic → (4) eliminate incompatible methods/options → (5) apply the simplest supported rule → (6) check → (7) move on if it's eating disproportionate time.

For written questions, state what partial work is still worth showing — but only where partial credit is plausible given the course's answer style.

## 10. Cross-source question mapping

Connect the same concept across sources: **Lecture concept → Worksheet practice → Past exam version → Model answer.**

When a structure recurs with different numbers, organisms, or wording, label it a **reusable question pattern** and explain the *invariant solving structure*. Never settle for "this topic repeats."

## 11. Professor-specific method preservation (strict)

When the professor consistently uses a particular procedure, notation, shortcut, classification, terminology, or answer structure, **teach that one for the exam** even if another valid method exists. On genuine conflict with textbook convention, follow the professor's and flag the discrepancy explicitly. Never silently "correct" the professor's terminology.

## 12. Error & contradiction audit

Before finalizing, audit for: incorrect answer keys · contradictory slides · inconsistent terminology · arithmetic errors · mislabeled diagrams · impossible answer choices · ambiguous questions · inconsistent professor methods · transcription and OCR errors · duplicated or missing pages.

Report each confirmed issue as: **SOURCE SAYS → PROBLEM → EVIDENCE FROM OTHER COURSE MATERIAL → WHAT TO FOLLOW FOR THE EXAM.**

Do not conceal source errors, and do not assume the textbook answer is what the professor grades.

## 13. Difficulty layering

Per high-priority topic, flag five levels so the student sees where preparation is weak: **Recognition** (can I identify it?) · **Basic** (straightforward question?) · **Application** (the professor's typical question?) · **Trap** (avoid the distractor?) · **Written** (complete answer under time pressure?).

## 14. Source-linked worked questions

Tag every worked question with its origin where possible: *Source: Midterm 2024, Q3* · *Source: Booklet p45, Example 2* · *Source: Lecture 7, Example 1* (same tag format as `prediction-and-analysis.md` §5). This lets the student return to the original and makes professor-derived examples obvious.

## 15. Time-budget prioritization ("if you have only X hours")

When the student gives a time limit or the exam is imminent, produce **TIME AVAILABLE → TOPICS → EXACT TASK**.

Order by: marks → past-exam recurrence → explicit professor emphasis → probability of appearing → difficulty → speed of mark gain (see `prediction-and-analysis.md` §1b). Skip anything dropped from scope (§0a). Never prescribe equal time across topics. For a beginner, front-load high-yield procedures and recurring question structures before low-yield theory.

## 16. Exam-room attack plan

When the exam is imminent, add an execution strategy fitted to the *actual* format, not a generic clock plan.

- **MCQ:** scan · answer the obvious · mark uncertain · flag calculation-heavy ones · return strategically · eliminate · check only high-risk answers.
- **Written:** identify all parts first · allocate time by marks (exam minutes ÷ total marks = minutes per mark) · write the method/formula before calculating · show intermediate work where partial credit exists · answer every subpart · reserve time for interpretation and checking.

## 17. Coverage audit (run before delivery)

Verify: every past-exam question type covered · recurring worksheet structures covered · every explicit professor cue covered · every major calculation procedure demonstrated · likely written-question structures demonstrated · every high-confidence prediction evidence-backed · source errors flagged · no important topic left without a "how to solve" · no topic over-weighted despite weak exam evidence.

Where a topic is important but has no real example, state plainly: **"Concept covered, but no professor-style example was found in the supplied material."**
